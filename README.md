# 综合规范页使用说明

## 当前结构

当前目录中的综合页已经切换为外部依赖模式，不再将源文档合并为单文件内嵌页。

三份核心规范的职责分工如下：

- `生信开发模块文件与输出规范.html`：模块目录、命名规范、日志与结果追踪
- `代码保护指南.html`：代码保护边界、交付限制、保护策略与红线清单
- `代码生成与验证流程图.html`：代码生成、验证、审核与交付流程

综合页还可按当前启用的页签引用数据处理、分析 SOP、培训等操作文档。不要在说明中硬编码总页数，应以 `综合规范与流程图.html` 的页签和 iframe 为准。

相关源文件如下：

- `生信开发模块文件与输出规范.html`：规范手册正文
- `代码保护指南.html`：代码保护与交付边界说明
- `代码生成与验证流程图.html`：流程手册正文
- `初步数据处理指南.html`：数据整理、输入校验与处理边界
- `标准化分析流程SOP.html`：已部署分析模块的真实入口、输入与输出说明
- `生信流程执行员培训手册.html`：培训材料；是否在综合页显示由当前页签配置决定
- `综合规范与流程图.html`：综合查看页，负责页签切换与嵌入展示
- `综合规范与流程图_bk.html`：综合查看页备份

## 维护方式

以后如需更新内容，直接修改源文件即可：

- 修改规范内容：更新 `生信开发模块文件与输出规范.html`
- 修改保护指南：更新 `代码保护指南.html`
- 修改流程图内容：更新 `代码生成与验证流程图.html`
- 修改具体操作说明：更新对应的数据处理、SOP 或培训源文件

综合页会通过 iframe 直接引用上述独立 HTML 文件，因此无需再做“重新合并”“Base64 内嵌”或“单文件重建”之类操作。

## 综合页约定

- `综合规范与流程图.html` 与 `综合规范与流程图_bk.html` 都应保持外部依赖模式
- 页面应保留以下能力：
  - 当前已启用文档的页签切换
  - iframe 自适应高度
  - 可单独打开源文件
- 当前模式标记为：`<!-- SINGLE_FILE=false -->`

## 最小检查清单

每次修改后建议检查：

1. `综合规范与流程图.html` 可以正常打开
2. 每个当前页签都能切换、加载对应源文件并单独打开
3. 三份核心规范的修改会直接在综合页中显示
4. 新增或移除页签时，按钮、页面容器、iframe、主题色映射和页脚版本说明同步更新
5. 所有本地 iframe 引用均指向存在的文件
6. 页面中文内容无乱码，HTML 结构校验通过

## 本轮增强边界

- 新建或升级模块使用阶段式 `./run.sh`，无参数显示帮助，`init` 只生成一份分析配置。
- `calculate` 发布可校验的正式计算缓存；`plot` 只从有效缓存重建模块约定的全部图形，不静默重新计算。
- 正式表格、图形和既有报告位置仍由主规范与模块 README 决定；未启用报告时不创建空报告目录。
- 所有业务与绘图参数均应有中文注释；图形格式、尺寸、主题、颜色和字体的实际生效值写入日志。
- SOP 中已部署模块的真实命令按其帮助说明保留；旧参数只作为明确记录的兼容接口，不复制到新模块。

## 说明

如果未来确实要恢复为单文件交付，需要单独重新设计交付方式；当前默认工作流应始终以“独立源文件 + 综合查看页”作为准则。
