BIOINFORMATICS · HUMAN-READABLE STANDARD

生信开发模块文件与输出规范

v2.2 将 v1.3 的可复现与报告质量要求，和 v2.1 的能力驱动原则合并为一套规则。模块以最小公开接口交付真实分析结果；复杂分析可以产生多个结果，但每个结果都必须回答独立问题、服务明确消费者，并受合同预算约束。

能力驱动，不凑阶段 先审源码，再写代码 计算开发 + 报告开发 结果、图件、报告同源

1. 权威源与适用范围

本页是统一 v2.2 的人类可读开发规范。项目需求确定目标，官方文档和方法论文定义应实现的科学语义，实际执行代码与数据定义本次实际结果，模块合同文件记录公开行为与产物；发生冲突时必须进入人工审定。规范中的 URL/DOI 只用于来源追溯，不会被自动写入报告正文。

存量模块不是模板。《标准化分析流程 SOP》记录已部署模块的真实入口和历史输出；它可以帮助定位兼容边界，但不能替代 v2.2 合同。DEGs 的报告链可作为“机械报告 coder”参考实现，不能把 DEGs 的科学字段硬套到其他模块。

2. 源码审定与开发分工

所有新建、迁移、算法/统计/绘图实质变更，在写新代码前先完成源码审定。只改报告内容或版式使用 report-only；只改不改变科学结果的作图实现使用 plot；只有计算、科学逻辑、配置、合同或输出结构变化使用 full。前两种场景可复用已发布结果，但不得凭空补科学事实。

  1. 计算开发：读取原始源码，收集对应的官方软件文档、方法论文和版本资料，写入模块 doc/source-review.md 及 doc/source-review/ 短记录，逐项核对数据含义、算法、统计、参数、方向和现有绘图逻辑；审定后负责计算与作图代码。
  2. 报告开发：读取已审定的源码结论和真实结果，编写模块报告模板、固定正文、动态结果描述、表格/图片插入、图题图注和 R/Python 报告生成器；运行时由该生成器机械出具报告。
比较项必须记录
官方定义来源名称、版本、URL/DOI、访问日期、关键规则和必要摘录。
源码实现入口、函数/脚本位置、实际参数、输入输出和绘图调用。
执行证据实际运行命令、结果表、图件、样本/对象统计和版本记录。
结论PASS、PROVISIONAL、DECISION_REQUIRED 或 BLOCKED。
冲突动作：官网定义与源码实现不一致时立即停止当前开发、作图和报告；生成一张决策卡，由指定人员选择保留实现、修改实现或暂不支持。决定前不得静默修正，也不得按官网图片替代实际结果。

3. 精简原则

一个事实一个位置
科学结果进表或图，解释进报告，运行事实进 run_record.json。
没有消费者就没有产物
“便于检查、以后可能用、证明已通过”不是正式消费者。
预算是上限
合同允许多个文件，不代表需要写满；删除不损失能力的文件必须删除。
要求不反向制造实现
没有报告、图、缓存或独立阶段的模块，不创建空能力和占位目录。
禁止：把审核表、证据包、阶段状态、参数回显、产物 manifest 或 checksum 作为公开业务结果。这些记录只用于开发与验证控制面；运行事实统一写入固定的 log/run_record.json，result/ 和正式报告只保留用户需要的业务产物。

4. 开发前冻结边界

边界必须回答
目标明确模块回答的业务或科学问题。
输入明确对象、字段、单位、物种、尺度和缺失值规则。
输出明确每个逻辑产物的用途、消费者和交付形式。
非目标明确本轮不支持的算法、平台、格式和兼容行为。
成功证据明确测试、不变量、渲染和人工复核的完成证据。
停止条件明确达到哪些产物和验证条件后停止增加功能。

先写最小真实合同，再写代码。演示输入可验证流程，但不能代替真实业务验证；不得用桩、模拟结果、占位文件或静默降级冒充实现。

5. 源码结构

module/
├── run.sh
├── README.md
├── module_contract.yaml
├── [doc/source-review.md] # 官方资料与源码交叉核对
├── [config/]             # 有配置或图件
├── [scripts/]            # 有入口外实现
├── [report_templates/]   # 生成报告
├── [demo/data/]          # 有受控演示输入
├── [schemas/]            # 有稳定数据结构
└── [docs/]               # 仅长期设计说明

方括号目录按真实能力创建。禁止空目录、.gitkeep 占位、模块内虚拟环境、历史输出、平行的 new/final/v2 实现和“以后可能用”的框架。doc/source-review.md 与 doc/source-review/ 是科学资料缓存和决策依据，不是运行日志或结果副本。

一次性运行审计、测试收敛和治理状态进入外部受控记录或 log/run_record.json；报告 coder 的模板和生成器是模块正式源码，不是临时审计文件。

6. 入口与命令

  • run.sh 是稳定公开入口，只负责解析、校验、调度、日志和发布。
  • 无参数或 --help 返回 0，且不创建任何文件；已公开的 -h 或 help 必须显示同一份帮助。
  • 帮助标题、功能说明、参数解释、运行约束、错误定位说明和示例注释以简体中文为主；命令、选项、路径、环境变量、API、包名、数据格式及必要专业术语保留英文标识。
  • 有配置时提供幂等 init；没有配置时不造空初始化命令。
  • calculate、plot、report 只是常用名称，不是固定套餐。
  • full 只用于两个及以上真实写阶段，等价于已声明子命令的组合。
  • 同一逻辑产物经不同命令生成时，路径、标题、字段语义、来源和配置必须一致。
只有一个不可再拆的业务流程时，使用一个原子写命令即可；没有图或报告的模块必须明确拒绝相应命令，而不是生成占位文件。

7. 配置合同：唯一、中文、真实生效

  • 每个模块只选 INI 或 YAML 一种主要格式，只保留一份规范配置模板，由 init 唯一读取。
  • 演示配置是演示输入的实例，不是第二套模板；不得维护两份默认值或两套参数语义。
  • 每个公开键都必须被生产路径读取、校验并影响声明行为；禁止 no-op、只回显、只写日志或永远被入口覆盖的参数。
  • 未知 section、未知键、非法行、越界值和不支持枚举必须立即失败。
  • 优先级固定为：命令行显式覆盖 ＞ 用户配置 ＞ 模块默认值。
  • 配置中的相对路径相对配置文件本身解析；运行时不得改写用户配置。

每个配置项的紧邻中文注释

注释至少写明用途及修改影响、类型、默认值、是否必填；枚举列出全部允许值，数值写范围、边界和单位，布尔值分别说明 true/false，路径写允许格式和相对基准，条件参数写依赖与互斥。

[plot.volcano]
# 火山图宽度；浮点数；单位 inch；范围 4–20（含边界）；默认 8；必填。
width = 8
# 输出格式；可多选：png=栅格图，pdf=矢量图；默认 png, pdf；必填。
formats = png, pdf
# 是否显示基因标签；true=显示配置数量的标签，false=不显示；默认 true；必填。
show_labels = true

8. 输出结构与结果准入

output/
├── .run_id
├── result/                 # 正式表、图、模型或数据交付
├── [report/]               # 确有独立解释用途时
├── [cache/]                # 确有下游复用时
└── log/
    ├── run_record.json       # 唯一运行事实与产物记录
    ├── [full.config.*]       # full 模式且有配置时
    ├── [calculate.config.*]  # calculate 模式且有配置时
    └── [command.log]         # 确有独立诊断价值时，每命令最多一份固定日志

结果文件准入测试

准入项通过条件
业务用途用途能直接描述消费者从文件得到的业务或科学结果。
删除影响删除后不能失去独立分析能力、必要交付格式或真实阶段衔接能力。
唯一权威性不得只是另一结果的裁剪或换格式；同一事实保留唯一权威结果。
交付性质不得仅用于审核、判断或证明；这类事实进入日志或外部验收系统。
数量预算展开维度、最大文件数和字节数在合同中可计算；0=无限 不通过。

DEGs 的紧凑输出示例

result/
├── 01.DEG_all.csv                 # 全部差异结果
├── 01.DEG_sig.csv                 # 合同声明的显著结果
├── 02.volcano.png                 # 火山图
├── 02.volcano.pdf
├── 03.heatmap.png                 # 有显著结果时
└── 03.heatmap.pdf

公开结果默认直接平铺在 result/ 根目录。01.DEG_sig.csv 这类筛选表只要在合同中声明了独立消费者和用途，就是正式结果；禁止的是没有消费者的重复裁剪、改名副本、阈值回显和仅供审核的文件。合法无发现时，已声明且下游需要 schema 连续性的表保留表头空表；不适用图件整项省略，不生成占位图。复杂模块可以有更多表、图、模型或数据包，但每项都必须通过同一个准入测试。

9. 每幅图必须单独可调

每个逻辑图拥有唯一命名空间 plot.<figure_slug>。即使模块只有一张图，也不得使用全局 [Plot]；没有图的模块不创建空绘图配置。图件必须由实际执行代码和数据生成，不能从官网图片重新绘制或替代。

配置组最低要求
尺寸与格式width、height、formats；栅格格式含 dpi。
文字font_family、base_font_size、title。
视觉编码palette 及该图真实需要的轴、图例、排序、分面、标签或显示范围。
展开图覆盖按完整方法/比较/队列组合进行稀疏 override，只影响目标图。
  • 只暴露消费者合理需要、实现确实支持的参数，不把所有绘图库内部常量塞进配置。
  • formats 要哪种格式就明确写出来，多种用逗号分隔（如 png, pdf）；不提供 both 这种一个词代指多种格式的缩写；默认输出 png, pdf 两种。
  • 每个配置参数必须通过测试证明真实影响对应图，且不会改变源科学数据。
  • 同源数据、字段映射、过滤、排序、图型和有效配置相同的图是同一逻辑图，不能靠换文件名重复发布。
  • 报告需要的兼容图片在临时渲染目录生成并清理，不得长期落入 result/report_images。
  • 官方资料规定的绘图方式与源码不一致时先进入 DECISION_REQUIRED；源码缺少官方方法确实需要的图，可在审定后作为新增分析实现，但必须用真实数据重新执行并声明新产物。
  • 报告嵌入完整源图；禁止裁剪、切片、拉伸或把一个 composite figure 拆成跨页续图。

10. 报告 coder 与机械报告

bio-report-writing 是报告 coder：它可以在独立调用时根据给定材料一次性写报告，也可以在模块开发时写出可复用的 DOCX 模板和 R/Python 生成器；两种场景遵守完全相同的内容、证据、图件和渲染规范。开发时由 AI/开发者编写并冻结模板，模块运行时由已提交的生成器机械填充出报告，不临场调用 AI 写作。

默认最多一份逻辑报告，位于 report/；DOCX、PDF、HTML 可以是同一报告的必要交付格式，但不得在 result/ 留正文或副本。

报告用途必须回答不得越界
科学解释设计、方法、关键定量事实、解释与边界因果或临床承诺
模型评估数据划分、指标、泛化风险与限制用训练集表现代替泛化证据
图形阅读数据源、视觉编码、可观察事实与阅读边界把视觉趋势写成统计证明
基准比较对象、数据集、指标、公平性与取舍边界隐藏不可比条件
  • 报告模板固定覆盖标题/摘要、范围、方法参数、QC（适用时）、结果与解释、综合结论、限制/待验证、公开输出、参考文献和版本等语义槽位；模块可合并相邻槽位，但不得丢失语义或生成空章节。
  • 结论先给量化事实和证据位置，再解释；“明显、较好、显著”不能代替数值和方向。
  • 每张图注说明对象、比较方向、单位或视觉编码及阅读边界。
  • 报告生成器只读已声明结果，不重新读原始输入、重算统计或临时重画未声明图片。
  • 渲染前按声明的来源产物与 Schema 失败关闭校验；缺少必需列、事实或图件时不得用 NA、错误文字或占位图继续发布。
  • 摘要截断、排序和选图必须由报告用途与正式结果字段驱动，禁止仅按文件名字典序取前 N 项。
  • 运行通过/失败、warning、文件清单、绝对路径、字节数、哈希和审核结果不进入报告。
  • 新模块默认以 report_templates/report_template.docx 为唯一正式正文模板，由 scripts/report/generate_report.R|py 按稳定 bookmark/marker 填充；存量 QMD/Rmd 只在迁移完成前由原 renderer 接线，必须遵守同一 v2.2 合同，不得并行维护第二套正文。
  • 模板固定结果表、公开输出表、软件/资源版本表、完整图件和条件 Note 的位置；Note 默认使用边框 #5B9BD5、填充 #DDEBF7、标签 #2F75B5，只由实际方向、单位或解释边界触发。
  • 按变更面运行：只改报告正文、图题、图注、表述或 DOCX 版式用已发布结果执行 report-only；只改不影响科学结果的作图实现执行 plot，随后用新图执行 report-only；只有计算/科学逻辑、配置、合同或输出结构变化才执行 full。报告层或纯绘图层变更不得被误判为科学结果变更。
  • 模块的模板、生成器和固定正文是正式源码；渲染中间文件、转换图、解压目录和其他 sidecar 只进临时工作区，发布前清理。
  • 任何 fallback 仍须满足同一内容与格式合同；缺图、缺表的“文本兜底版”必须失败。

11. 日志与缓存

日志

log/run_record.json 是运行事实唯一权威源，记录执行 ID、命令、状态、输入与配置指纹、合同哈希、软件版本、随机种子、产物路径/大小/哈希/来源以及逐图请求值和实际渲染值。

默认不拆分日志；确有独立诊断价值时，每个公开写命令最多保留一份固定日志，不按时间戳无限追加。

缓存

cache/ 只保存后续计算、绘图或报告重建真实消费的有版本对象。结构版本、来源与参数指纹、run ID 和校验和写入缓存对象自身，不另生成 cache_manifest.json。

纯 plot.* 参数不应使科学计算缓存失效；缓存缺失或无效时后续阶段明确失败，不得静默重算。

12. 代码精简、可读、可维护

  • 主流程按“解析 → 校验 → 执行 → 验证 → 原子发布”阅读。
  • 一个业务规则只有一个实现；优先删除和复用，再增加抽象。
  • 函数职责清晰、输入输出显式；避免万能大文件、一函数一文件和无意义转发层。
  • 删除死代码、注释掉的旧实现、无调用 helper 和无调用方兼容层。
  • run.sh 不承载大段算法、绘图或报告逻辑。
  • 核心算法、统计口径、比较方向、单位转换、状态判定、兼容分支和关键不变量附近写简洁中文注释，说明“为什么、边界和改动风险”。
  • 新增或修改的 R/Python/Shell 业务代码注释统一使用简体中文；函数名、变量名、包名、公式和标准技术术语保留英文原文。
  • 不要逐行翻译代码或用注释凑覆盖率；直观搬运和薄包装不要求中文注释。

13. 验收与存量迁移

合同
路径、引用、数量、大小、条件和输出树通过共享校验。
配置
唯一模板、中文注释、Schema 一致，所有公开键真实接线。
结果
每个文件通过删除测试，无未声明文件、空目录和证据副产物。
图件
逐图参数集合一致、展开隔离、代表性参数真实生效。
源码审定
doc/source-review.md 已完成官方定义、源码实现和执行证据交叉核对；冲突已审定。
报告
报告 coder 的模板/生成器可运行，事实可追溯、内容不越界、sidecar 清理，并完成真实格式渲染。
代码
语法、算法不变量、原子发布、路径安全、精简性和中文注释通过复核。
迁移规则：旧模块先记录原始入口、核心脚本、配置、主要输出、绘图逻辑和报告逻辑，再完成源码审定并批准具体升级范围；不要为了统一一次性重写所有旧模块。旧 HTML、SOP 或 README 不能作为科学逻辑、图件或报告保真的豁免依据。

完成不是再生成一份验收清单：边界已冻结、适用测试与真实验证通过、README/Wiki/CodeGraph 按仓库规则同步，并已核对停止条件，即停止继续加文件和功能。
