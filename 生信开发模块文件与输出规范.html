报告位置是模块契约，不是双写规则： 上例沿用 result/。只有模块 README 明确声明独立报告目录时，才按需创建 report/ 并把报告放在那里；同一正式报告不得在两个目录重复生成。
📌 使用约定： 新建或进入本轮升级范围的模块，对外统一由顶层 run.sh 作为唯一主入口；scripts/ 用于存放内部实现脚本，后续如需保护处理（如加密、编译、二进制化等）也应只影响内部实现，不改变外部使用方式。尚未升级的已部署模块可继续保留公开的 run_*.sh，以模块 README 和 --help 为准，不因本目录示例被机械改名。

📦 结果边界： 运行日志、分析结果、报告属于独立的模块结果目录，不要和脚本模块根目录混放。

目录说明

📂 scripts/ - 内部实现脚本目录

  • 顶层入口固定：新建或进入升级范围的模块统一执行顶层 run.sh，不直接面向 scripts/ 内部脚本；未升级模块仍以已公开入口为准
  • 存放该模块的内部实现脚本（.R、.py、.sh 等），可由 scripts.sh 或其他调度脚本串联执行
  • 内部实现可调整：scripts/ 内部脚本后续可做保护处理（如加密、编译、二进制化等）、替换或重构，但应保持 run.sh 的对外调用方式稳定
  • 路径处理统一：所有输入、输出、配置、日志路径在使用前都应先做 normalizePath 或等价标准化处理，禁止直接拼接原始路径字符串后立即读写文件
  • 计算与作图分离：同一分析点的计算逻辑和可视化逻辑应拆分为独立脚本，如 DEGs_analysis.R（差异计算）与 DEGs_plot.R（热图/火山图等），便于只改图时不必重跑计算、提高复用性和调试效率
  • 脚本命名使用驼峰命名法，清晰表明功能，建议按分析流程顺序命名
  • 配置模板：在 config/ 下保存模块选定格式的一个示例配置（*.config.example.*）
  • 模板与运行配置分离：模块内 config/ 只保存只读示例模板；init 在用户指定的项目目录生成一份分析配置；每次运行再把输入配置与解析后的生效参数写入 module_output/log/<run_id>/
  • 读取文件推荐：R脚本推荐使用 data.table 包
  • 示例：
    • run.sh - 模块对外执行入口
    • scripts/RawData.R - 原始数据处理内部脚本
    • scripts/DEGs_analysis.R - 差异表达计算脚本
    • scripts/DEGs_plot.R - 差异表达可视化脚本
    • scripts/scripts.sh - 内部流程调度脚本
    • config/DEGs.config.example.yaml - 参数模板
💡 计算与作图分离 — 实施约定
  • 中间结果格式：计算脚本将分析结果保存为 .qs2（R）或 .tsv/.csv（通用表格：含化合物名、药物名、描述等可能带逗号字段时用 TSV；确认无逗号解析风险时可用 CSV），作图脚本直接读取中间结果文件，不重复执行计算逻辑
  • 正式缓存位置：绘图可复用的正式计算对象统一写入 module_output/cache/；仅供单次运行使用、失败后可丢弃的临时文件才放入 _tmp/，二者不得混用
  • 命名规范：计算脚本以 _analysis 结尾，作图脚本以 _plot 结尾，如 DEGs_analysis.R / DEGs_plot.R、GSEA_analysis.R / GSEA_plot.R
  • 调度串联：scripts.sh 或 run.sh 中先调用计算脚本再调用作图脚本，并支持 ./run.sh plot 从有效缓存重建全部图形而不触发计算；既有 --plot-only 只能作为明确记录的兼容别名
  • 参数传递：作图脚本的可视化参数（色板、字号、图幅尺寸等）应独立于分析参数，可在配置文件中设专用 [Plot] 段
  • 日志独立：如计算和作图分开运行，各自的日志应能独立追溯；若串联运行，可合并到同一份日志中按步骤分段记录
📝 计算与缓存发布示例（DEGs_analysis.R，关键逻辑）： 
# 输入：表达矩阵 + 分组信息
# 输出：正式表格 + 足以绘制全部约定图形的命名对象
library(data.table)
library(DESeq2)
library(qs2)

expr_mat  <- fread(normalizePath(input_expr), data.table = FALSE)
group_info <- fread(normalizePath(input_group), data.table = FALSE)

dds <- DESeqDataSetFromMatrix(expr_mat, group_info, design = ~group)
dds <- DESeq(dds)
de_table <- as.data.frame(results(dds, alpha = p_cutoff))
de_table$significance <- "NotSignificant"
de_table$significance[!is.na(de_table$padj) & de_table$padj < p_cutoff &
                          de_table$log2FoldChange >= log2fc_cutoff] <- "Up"
de_table$significance[!is.na(de_table$padj) & de_table$padj < p_cutoff &
                          de_table$log2FoldChange <= -log2fc_cutoff] <- "Down"

normalized_mat <- assay(vst(dds, blind = FALSE))
top_index <- head(order(apply(normalized_mat, 1, var), decreasing = TRUE), 100)
plot_cache <- list(
    de_table = de_table,
    top_genes_mat = normalized_mat[top_index, , drop = FALSE],
    heatmap_annotation = group_info
)

fwrite(de_table, file.path(result_dir, "01.DEGs.tsv"), sep = "\t")

# 每次生成不可变代次；input_fingerprint / compute_fingerprint 由稳定序列化规则计算
generation_rel <- file.path("generations", run_id)
generation_dir <- file.path(cache_dir, generation_rel)
staging_dir <- file.path(cache_dir, paste0(".staging-", run_id))
if (dir.exists(generation_dir) || dir.exists(staging_dir)) stop("缓存代次已存在")
dir.create(staging_dir, recursive = TRUE)
artifact_tmp <- file.path(staging_dir, "calculation.qs2")
qs2::qs_save(plot_cache, artifact_tmp)

manifest <- list(
    schema_version = 1,
    module = list(name = "DEGs", version = module_version),
    producer_run_id = run_id,
    created_at = format(Sys.time(), "%Y-%m-%dT%H:%M:%S%z"),
    input_fingerprint = input_fingerprint,
    compute_fingerprint = compute_fingerprint,
    artifacts = list(list(
        path = file.path(generation_rel, "calculation.qs2"),
        sha256 = digest::digest(file = artifact_tmp, algo = "sha256"),
        size = unname(file.info(artifact_tmp)$size)
    )),
    plot_contract = list(figures = c("02_heatmap", "03_volcano")),
    runtime = list(
        R = R.version.string,
        Rscript = normalizePath(file.path(R.home("bin"), "Rscript")),
        qs2 = as.character(packageVersion("qs2"))
    )
)

# 校验 staging 后先发布不可变对象，最后原子替换顶层 manifest 作为提交点。
# 若最后一步失败，旧 manifest 仍指向旧的有效代次；新代次只会成为可清理孤儿。
validate_staged_cache(plot_cache, manifest, artifact_tmp)
dir.create(dirname(generation_dir), recursive = TRUE, showWarnings = FALSE)
if (!file.rename(staging_dir, generation_dir)) stop("缓存对象发布失败")
manifest_tmp <- file.path(cache_dir, paste0("cache_manifest.json.tmp.", run_id))
jsonlite::write_json(manifest, manifest_tmp, auto_unbox = TRUE, pretty = TRUE)
if (!file.rename(manifest_tmp, file.path(cache_dir, "cache_manifest.json"))) {
    stop("缓存清单发布失败；当前有效清单未改变")
}

⚙️ 业务阶段调度示例（仅展示后文完整入口解析参数后的内部调度）： 
#!/usr/bin/env bash
set -euo pipefail

MODULE_DIR=$(cd -- "$(dirname -- "${BASH_SOURCE[0]}")" && pwd)
run_business_stage() {
    local stage=$1
    shift
    case "$stage" in
        calculate) Rscript "$MODULE_DIR/scripts/DEGs_analysis.R" "$@" ;;
        plot)      Rscript "$MODULE_DIR/scripts/DEGs_plot.R" "$@" ;;
        full)
            Rscript "$MODULE_DIR/scripts/DEGs_analysis.R" "$@"
            Rscript "$MODULE_DIR/scripts/DEGs_plot.R" "$@"
            ;;
        *) return 2 ;;  # 阶段白名单由入口骨架先行校验
    esac
}
💡 为什么推荐 data.table？
  • 高性能：比 base R 快得多，处理大数据集更高效
  • 内存友好：内存占用更少，可处理超过内存大小的数据集
  • 语法简洁：语法一致性好，学习曲线平缓
  • 功能丰富：类似 SQL 的语法，操作直观
  • 并行处理：支持多线程并行计算

📄 log/ - 日志文件夹 核心

  • 存放各阶段或模块入口的运行日志，推荐使用单数目录 log/，与 chromosome_plot 示例保持一致
  • 每次实际运行使用 log/<run_id>/<stage>.log，如 log/20260806_143022/plot.log；帮助与 init 不创建运行日志
  • 运行标识：日志从启动起记录本次 run_id、命令、阶段、输出目录和退出码；仅在该次调用成功完成后原子更新模块结果目录顶层 .run_id
  • 缓存追溯：绘图日志同时记录当前绘图 run_id 和缓存生产 run_id，不得用当前 run_id 覆盖缓存来源
  • 支持中文：日志内容可以使用中文，便于理解和阅读

📊 result/ - 结果文件夹

  • 存放正式用户结果：表格、图和最终报告；可复用对象放 cache/，日志和配置副本放 log/
  • 结果文件使用数字前缀排序（01_, 02_, 03_ 或 01., 02., 03.），文件名表达业务含义
  • 模块结果目录顶层 .run_id 只指向最近一次成功调用；失败运行仍保留自己的日志，但不得覆盖成功标识
  • 配置文件：本次输入快照与生效参数分别写入 log/<run_id>/input.config.* 和 effective.config.*
  • 图表文件：默认同时保存 PNG 和 PDF；模块也可按 [Plot].formats 生成经过校验的请求格式
  • 示例：
    • 01_gene_positions.tsv - 表格结果（含逗号风险用 TSV；无逗号问题可用 CSV）
    • 02_circos.png + 02_circos.pdf - 图表（双格式）
    • chromosome_plot_report.docx - 正式报告
    • .run_id - 隐藏运行标识文件，内容是最近一次成功调用的 run_id

📝 report/ - 可选报告文件夹

  • 正式报告默认可直接放入 result/；只有模块 README 明确声明独立报告目录时才使用本目录
  • 仅在报告阶段实际启用并成功产出报告时按需创建，禁止预建空目录
  • 报告文件名应表达模块或报告含义，如 chromosome_plot_report.docx
  • 报告路径和对应 run_id 写入该次运行日志，由 .run_id 定位最近成功调用
  • 便于追溯某次分析的具体结果和参数
  • 默认格式：报告默认使用 .docx 格式
  • 推荐工具：推荐使用 Quarto 生成报告
  • 示例：
    • chromosome_plot_report.docx - chromosome_plot 正式报告（默认）
    • DEGs_report.docx - DEGs 模块正式报告
💡 为什么推荐 Quarto？
  • 代码与报告一体：代码和报告在同一个文档中，便于同步更新
  • 多语言支持：支持 Python、R、Julia 等多种语言
  • 多种输出格式：可输出 HTML、PDF、Word、PPT；默认输出 .docx
  • 可复现性：包含完整代码，确保分析可复现
  • 版本控制：Markdown格式便于 Git 管理

🚀 运行阶段、正式缓存与配置生命周期

⚠️ 核心契约： 新建或升级后的模块统一使用顶层 run.sh 和阶段式入口。正式计算产物写入 cache/，绘图阶段只读取有效缓存并重建全部图形结果，不得静默回退为重新计算。帮助、初始化和各运行阶段只创建自身确实需要的文件与目录。

统一阶段与副作用

调用职责允许产生的内容禁止行为
./run.sh
./run.sh --help		显示模块用途、阶段、参数、输入模式、输出和示例；正常返回 0仅向 stdout 输出帮助不得创建 .run_id、日志或任何输出目录
./run.sh init --target DIR从模块模板生成一份可编辑的分析配置DIR/config/<module>.config.<ext>不得同时生成多份等价分析配置，不得预建 log/、cache/、result/ 或 report/
./run.sh calculate --config FILE --output DIR校验输入并执行正式计算正式表格、有效计算缓存和本阶段日志不得生成图形或空报告目录
./run.sh plot --config FILE --output DIR校验并读取已有正式缓存，重新生成该模块约定的全部图形请求格式的图形和本阶段日志不得调用计算脚本；缓存无效时不得静默重算
./run.sh report ...仅适用于明确支持独立报告阶段的模块正式报告及日志；目录按需创建不支持报告的模块不得暴露空阶段或预建空 report/
./run.sh full ...按顺序执行计算、绘图，以及模块明确支持且已启用的报告阶段各已执行阶段的正式产物和日志不得无条件创建未启用阶段的目录

入口与参数规则

规则要求说明
稳定长参数统一使用 --config、--output、--target、--force 和 --help短参数仅在不与既有业务参数冲突时作为别名；不得跨模块强制规定 -c
直接执行run.sh 必须带 shebang 和可执行权限，README 示例统一使用 ./run.sh不能只保证 bash run.sh 可用
工作目录无关模块内部脚本和模板路径以 run.sh 所在目录为基准命令行相对路径以调用者当前目录为基准；配置内相对路径以配置文件所在目录为基准，解析后写入日志
参数错误未知阶段、未知参数、缺失参数和互斥组合均输出明确错误并非零退出错误信息同时给出 --help 提示，不创建正式产物
按需建目录完成参数与路径校验后，仅为当前阶段创建所需目录init、帮助和失败的前置校验不得留下空运行目录

正式计算缓存契约

契约项强制要求目的
内容边界缓存必须包含绘制该模块全部图形所需的完整计算对象或标准化绘图数据；正式表格和报告仍属于 result/ 或模块声明的报告目录“从缓存重绘”不等同于恢复所有表格和报告

🔗 结果追踪机制

✨ 核心设计： 程序开始时在内存中生成当前 run_id，并立即写入该次运行日志；全部校验和目标阶段成功后才原子更新模块结果目录顶层 .run_id。缓存另存生产 run_id，报告用业务含义命名。

🔄 run_id 生成和使用流程

  1. 解析阶段：无参数或 --help 直接显示帮助；其他调用先解析参数、校验阶段、配置、输入和输出边界，不提前创建产物目录
  2. 开始运行：为实际计算、绘图或报告调用生成当前 run_id，创建 log/<run_id>/，记录命令、配置来源、运行目录、输出目录和上游引用
  3. 阶段编排：由 run.sh 调度计算、作图、报告或全流程；业务算法保留在内部脚本中，未启用阶段不创建目录
  4. 保存结果：正式用户结果写入 result/；绘图可复用的正式计算对象和清单写入 cache/；一次性临时文件写入 _tmp/
  5. 保存追溯快照：写入输入配置快照和生效参数，不覆盖用户分析配置；绘图日志保留缓存生产 run_id
  6. 成功发布：校验目标阶段产物后原子更新 .run_id；失败调用保留日志但不得伪装成最近成功运行

🔗 追溯关系

  • 结果 → 日志：通过模块结果目录顶层 .run_id 读取最近一次成功调用的 run_id，再进入对应日志目录
  • 结果 → 参数：通过 log/<run_id>/effective.config.* 和阶段日志查看最终生效参数
  • 日志 → 报告：通过日志中的 run_id 和报告路径找到对应的分析报告
  • 完整链条：run.sh → 输入配置与生效快照 → 内部脚本 → 日志 → cache 正式计算对象 → result 正式结果 → 可选报告
  • 阶段引用：后一阶段只能读取前一阶段公开约定的标准产物，不应扫描临时目录或依赖未文档化的内部文件
  • 命名一致：单阶段运行与 full 全流程运行应生成同名同义的正式结果，避免下游因运行方式不同而改解析规则
  • 查找最近成功运行：读取 .run_id，再进入同名 log/<run_id>/；不能用目录排序代替成功状态

🛣️ 路径规范与 normalizePath 要求

⚠️ 核心原则： 凡是进入分析流程的文件路径、目录路径、配置路径、日志路径和输出路径，都必须先经过 normalizePath 或等价标准化处理。 目标是避免 Windows/Linux/macOS 下因分隔符、相对路径、冗余层级或软链接差异导致的读取失败、重复输出和日志不可追溯。

📏 标准化规则

规范项要求说明
统一预处理路径在存在性校验、读写、复制、移动、日志记录前必须先标准化不得一部分用原始路径、一部分用标准化路径
消除冗余层级自动折叠 .、..、重复分隔符等冗余片段避免相同文件被当成不同路径
分隔符一致内部处理推荐统一为标准化后的系统合法路径；日志展示建议统一为可读性更高的单一风格避免同一日志中同时出现 \\ 与 / 混用
绝对路径优先进入核心分析步骤前，关键输入输出路径应转换为绝对路径或可唯一定位的规范路径便于跨目录调用和问题追踪
软链接与真实路径如语言/平台支持，应尽量解析到真实路径并在日志中记录避免链接路径与真实路径混淆
日志一致性日志、配置、报告中引用的同一文件路径应保持一致禁止日志写相对路径、报告写另一套绝对路径

🧪 必须使用 normalizePath 的场景

  • 读取输入文件：如 group.csv、expression.csv、gene.csv、survival.csv、参考注释文件等
  • 写出结果文件：如 result/、report/、log/ 下的所有输出
  • 读取配置参数：配置文件中的路径字段读取后必须立即标准化，不能原样透传到后续流程
  • 跨语言调用：run.sh 调用 R/Python/其他脚本时，传递前先做标准化，避免脚本间路径口径不一致
  • 文件关联追溯：隐藏追踪文件、日志文件、报告文件之间的路径引用必须基于同一套标准化结果
  • 存在性与权限校验：先 normalizePath，后 file.exists/access，避免校验对象与实际读写对象不是同一路径
补充要求： 用户输入路径、配置路径、命令行参数路径都视为不可信原始值，必须先标准化再参与拼接、判断和输出。

if (!file.exists(input_file)) {

}

🚨 错误处理与退出码规范

规范项要求说明
退出码约定0 = 成功；1 = 一般错误；2 = 输入校验失败；3 = 依赖/环境异常上游调度脚本根据退出码判断是否继续
Shell 错误传播set -euo pipefail 必须写在 run.sh 和所有 .sh 脚本头部任何命令失败立即终止，未定义变量报错，管道中任一环节失败即失败
R 错误捕获关键分析步骤使用 tryCatch 包裹，失败时写日志并 quit(status = 1)禁止裸 stop() 后不做日志记录
Python 错误捕获入口函数使用 try/except，异常写入日志后 sys.exit(1)禁止 except: pass 或静默吞异常
日志联动错误信息必须同时输出到 stderr 和日志文件便于交互式调试和离线追溯
清理机制Shell 使用 trap cleanup EXIT；R/Python 使用 on.exit / finally确保异常退出时临时文件被清理、日志被刷盘
R 错误处理示例： 
tryCatch({
    dds <- DESeq(dds)
}, error = function(e) {
    log_error(paste0("DESeq2 分析失败: ", conditionMessage(e)))
    quit(status = 1)
})
Python 错误处理示例： 
try:
    result = run_analysis(config)
except Exception as e:
    logger.error(f"分析失败: {e}")
    sys.exit(1)

set -euo pipefail

MODULE_DIR=$(cd -- "$(dirname -- "${BASH_SOURCE[0]}")" && pwd)

usage() {
    cat <<EOF
用途: 对表达矩阵和分组信息执行差异分析，并支持从正式缓存独立绘图。
用法: $(basename "$0") <init|calculate|plot|full> [选项]

阶段:
  init      在 --target 下生成一份带中文注释的分析配置
  calculate 校验输入、输出正式表格并发布绘图所需缓存
  plot      只校验和读取已有缓存，重建全部约定图形
  full      依次执行 calculate + plot

输入模式:
  业务输入由 --config 指定；命令行只接受帮助中列出的合法覆盖项。
  配置内相对路径以配置文件目录为基准，解析后的绝对路径写入日志。

选项:
  --target DIR   init 的目标目录
  --config FILE  calculate / plot / full 的分析配置
  --output DIR   calculate / plot / full 的独立结果目录
  --force        仅 init 使用；覆盖前保留有界回滚副本
  -h, --help     显示本帮助

输出与边界:
  result/ 保存正式表格和图形；cache/ 保存可校验的正式计算缓存；
  log/<run_id>/ 保存日志和配置快照。plot 不重新计算，本模块不提供独立 report 阶段。

示例:
  $(basename "$0") init --target ./project
  $(basename "$0") full --config ./project/config/DEGs.config.ini --output ./output

}

require_value() {
    local option=$1 value=${2:-}
    if [[ -z "$value" || "$value" == -* ]]; then
        die_usage "参数缺少值: $option"
    fi
}

die_usage() {
    echo "错误: $*" >&2
    echo "运行 $(basename "$0") --help 查看帮助" >&2
    exit 2
}

if [[ $# -eq 0 || "${1:-}" == "-h" || "${1:-}" == "--help" ]]; then
    usage
    exit 0
fi

STAGE=$1
shift
case "$STAGE" in
    init|calculate|plot|full) ;;
    *) die_usage "未知阶段: $STAGE" ;;
esac

CONFIG=""
OUTPUT_DIR=""
TARGET_DIR=""
FORCE=false
while [[ $# -gt 0 ]]; do
    case "$1" in
        --config) require_value "$@"; CONFIG=$2; shift 2 ;;
        --output) require_value "$@"; OUTPUT_DIR=$2; shift 2 ;;
        --target) require_value "$@"; TARGET_DIR=$2; shift 2 ;;
        --force) FORCE=true; shift ;;
        -h|--help) usage; exit 0 ;;
        *) die_usage "未知参数: $1" ;;
    esac
done

# 先做阶段互斥校验；帮助与 init 不创建运行目录。
if [[ "$STAGE" == "init" ]]; then
    [[ -n "$TARGET_DIR" ]] || die_usage "init 必须提供 --target"
    [[ -z "$CONFIG" && -z "$OUTPUT_DIR" ]] || die_usage "init 不接受 --config 或 --output"
    INIT_ARGS=(--target "$TARGET_DIR")
    [[ "$FORCE" == true ]] && INIT_ARGS+=(--force)
    "$MODULE_DIR/scripts/init_config.sh" "${INIT_ARGS[@]}"
    exit 0
fi

[[ -n "$CONFIG" && -n "$OUTPUT_DIR" ]] || die_usage "$STAGE 必须提供 --config 和 --output"
[[ -z "$TARGET_DIR" && "$FORCE" == false ]] || die_usage "$STAGE 不接受 --target 或 --force"

# 这里只校验参数、输出写入边界和日志目录边界，不读取正式缓存。
"$MODULE_DIR/scripts/validate_arguments.sh" "$STAGE" "$CONFIG" "$OUTPUT_DIR"
RUN_ID="$(date +%Y%m%d_%H%M%S)_$$"
LOG_DIR="$OUTPUT_DIR/log/$RUN_ID"
mkdir -p "$LOG_DIR"
exec > >(tee "$LOG_DIR/$STAGE.log") 2>&1
printf 'run_id=%s stage=%s command=%s cwd=%q\n' "$RUN_ID" "$STAGE" "$RAW_COMMAND" "$PWD"

# 输入、配置和缓存校验发生在日志初始化之后，拒绝原因因此可以追溯。
"$MODULE_DIR/scripts/validate_runtime.sh" "$STAGE" "$CONFIG" "$OUTPUT_DIR" || {
    status=$?; printf 'exit_code=%s status=validation_failed\n' "$status"; exit "$status";
}
"$MODULE_DIR/scripts/run_stage.sh" "$STAGE" "$CONFIG" "$OUTPUT_DIR" "$RUN_ID" || {
    status=$?; printf 'exit_code=%s status=stage_failed\n' "$status"; exit "$status";
}

# 全部阶段与产物校验成功后，才更新最近成功运行标识。
RUN_ID_TMP="$OUTPUT_DIR/.run_id.tmp.$RUN_ID"
printf "%s\n" "$RUN_ID" > "$RUN_ID_TMP"
mv -f "$RUN_ID_TMP" "$OUTPUT_DIR/.run_id"
printf 'exit_code=0 status=success\n'

✅ 推荐做法

  • 区分运行来源：程序开始时生成当前 run_id 并写入日志，成功后才更新 .run_id；复用缓存时另行保留缓存生产 run_id
  • 日志优先：无论是否有配置文件，日志中必须详细记录所有参数
  • 配置文件简洁：模块选择 INI 或 YAML 中的一种主要格式；init 生成一份分析配置，运行只保存快照而不覆盖用户配置
  • 日志使用中文：日志内容可以使用中文，便于理解和阅读
  • 计算与作图分离：同一分析点的计算脚本和作图脚本拆成独立文件，改图时无需重跑计算
  • 图形格式可配置：默认同时保存 PNG 和 PDF，也可按配置生成模块支持的格式；验收以请求格式清单为准
  • 统一路径标准化：所有路径在校验、读写、记录前先做 normalizePath 或等价处理，并在日志中保持一致口径
  • 图表字体可追溯：默认使用 sans-serif；可配置已安装且模块支持的字体，缺失时应报错或按声明回退并写入日志
  • 色板标准：推荐使用 ggsci::npg、RColorBrewer 等学术配色方案；图表必须对色盲友好，避免仅靠红/绿区分数据
  • 使用 .qs2：R数据使用 .qs2 格式保存（qs2 R 包，替代 .rds/.RData）
  • 使用 data.table：读取文件推荐使用 data.table 包
  • 使用 Quarto：生成报告推荐使用 Quarto，默认输出 .docx 格式
  • 错误即终止：Shell 脚本固定 set -euo pipefail；R/Python 必须 tryCatch/try-except 并以非零退出码终止
  • 输出自检：脚本结束前自动校验输出文件存在性、非空、关键列完整
  • README.md 完备：每个模块必须包含标准 README（用途、依赖、输入输出、运行示例）
  • CHANGELOG.md：语义化版本号 + 每次变更记录
  • demo 验证：如提供 demo，只在 demo/data/ 放输入数据和必要配置；输出由本次运行现场生成
  • 按模块声明的保留策略清理过期日志和一次性临时结果；正式计算缓存不得作为临时文件自动删除
  • 使用版本控制系统（Git）管理scripts文件夹中的脚本
  • 为重要分析结果创建README.md说明文件内容
  • 定期备份result和report文件夹到云端或外部存储
  • 日志文件使用结构化格式，便于后续检索和分析
  • 在日志开头添加摘要部分，包含关键统计信息

❌ 避免做法

  • 使用无意义的文件名（如 result1.tsv, final.pdf）
  • .run_id 内容只精确到日期，导致同一天多次运行无法区分
  • 日志只记录运行成功/失败，不记录具体参数
  • 依赖配置文件而忽略日志的参数记录功能
  • 不保留日志文件，导致无法追溯分析过程
  • 结果文件与日志中的 run_id 无法对应
  • 用当前绘图 run_id 覆盖缓存生产 run_id，导致无法识别复用来源
  • 跳过路径标准化：直接用命令行输入、配置值或字符串拼接后的路径做存在性校验和文件读写
  • 把 run_id 或时间戳写进配置文件名，导致文件夹碎片化
  • 计算与作图混写：把数据计算和可视化代码写在同一个脚本中，导致改图必须重跑全部计算
  • 忽略格式配置：未生成用户请求的受支持格式，或仍按固定双格式验收
  • 字体行为不透明：配置字体不可用时静默替换，且日志不记录实际使用字体
  • 使用 .rds/.RData：推荐使用更现代的 .qs2 格式（qs2 R 包）
  • 使用 base R：推荐使用更高效的 data.table
  • 静默吞异常：except: pass 或裸 tryCatch 不记录错误信息
  • 缺少 shebang/安全模式：Shell 脚本不写 #!/usr/bin/env bash 和 set -euo pipefail
  • 模块间内存传递：通过全局变量或共享内存传递数据，不走文件接口
  • 输出不校验：脚本执行完不检查输出文件是否完整和正确
  • 无 README / 无版本号：模块缺少文档或依赖说明，新人无法独立运行
  • 敏感数据入库：将含患者真实 ID 的临床表提交到 Git 仓库

# 输出校验函数
validate_output <- function(file_path, required_cols = NULL) {
    if (!file.exists(file_path)) stop("输出文件缺失: ", file_path)
    if (file.size(file_path) == 0) stop("输出文件为空: ", file_path)

    if (grepl("\\.(tsv|csv)$", file_path)) {
        df <- data.table::fread(file_path, nrows = 5)
        if (!is.null(required_cols)) {
            missing <- setdiff(required_cols, names(df))
            if (length(missing) > 0) stop("缺少关键列: ", paste(missing, collapse = ", "))
        }
    }
    log_info(paste0("校验通过: ", file_path))
}

# demo 目录只提供输入数据和配置；输出由本次运行现场生成

[[ ! -e "$DEMO_OUTPUT" ]] || {
    echo "[FAIL] 输出已存在，请指定新的 demo 输出目录: $DEMO_OUTPUT" >&2
    exit 2
}

RUN_ID=$(tr -d '\r\n' < "$DEMO_OUTPUT/.run_id")
LOG_FILE="$DEMO_OUTPUT/log/$RUN_ID/full.log"

# 只检查关键产物是否由本次运行生成，不与预先保存的输出文件做 diff
for f in "$DEMO_OUTPUT/.run_id" "$LOG_FILE" "$DEMO_OUTPUT/cache/cache_manifest.json" "$DEMO_OUTPUT/result/01_gene_positions.tsv" "$DEMO_OUTPUT/result/02_circos.png" "$DEMO_OUTPUT/result/02_circos.pdf"; do
    if [ ! -s "$f" ]; then
        echo "[FAIL] 文件缺失或为空: $f"
        exit 1
    fi
done

# 同时验证 manifest 指向的不可变缓存对象非空、未越界且校验和一致
Rscript --vanilla - "$DEMO_OUTPUT/cache" <<'RS'
args <- commandArgs(trailingOnly = TRUE)
cache_dir <- normalizePath(args[[1]], mustWork = TRUE)
manifest <- jsonlite::read_json(file.path(cache_dir, "cache_manifest.json"), simplifyVector = FALSE)
if (length(manifest$artifacts) < 1L) stop("manifest 未声明缓存对象")
if (length(manifest$plot_contract$figures) < 1L) stop("manifest 未声明绘图契约")
artifact <- manifest$artifacts[[1L]]
artifact_path <- normalizePath(file.path(cache_dir, artifact$path), mustWork = TRUE)
cache_prefix <- paste0(cache_dir, .Platform$file.sep)
if (!startsWith(artifact_path, cache_prefix)) stop("manifest 缓存路径越界")
if (file.info(artifact_path)$size != as.numeric(artifact$size)) stop("缓存大小不匹配")
actual_sha256 <- digest::digest(file = artifact_path, algo = "sha256")
if (!identical(tolower(actual_sha256), tolower(artifact$sha256))) stop("缓存校验和不匹配")
RS

echo "=== demo 验证完成：仅代表 demo 输入跑通 ==="

# DEGs — 差异基因分析模块

> 版本: v1.2.0 | 更新: 2026-03-26

## 简介

基于 DESeq2 进行差异基因分析，输出差异基因列表、热图和火山图。

## 环境依赖

- R >= 4.2
- 关键包：DESeq2, data.table, ggplot2, qs2, pheatmap
- 完整依赖：`renv.lock`

## 上游模块依赖

| 上游模块 | 所需文件                           | 最低版本 |
|---------|-----------------------------------|---------|
| RawData | result/RawData/01.GSEXXX_count.csv | v1.0    |

## 快速开始

```bash
# 查看帮助（无参数同样只显示帮助）
./run.sh

# 生成一份带中文注释的分析配置
./run.sh init --target ./project

# 完整运行（计算 + 作图）
./run.sh full --config ./project/config/DEGs.config.ini --output ./output

# 仅从有效正式缓存重新作图
./run.sh plot --config ./project/config/DEGs.config.ini --output ./output
```

| 文件              | 格式  | 关键列            | 说明           |
|------------------|------|------------------|---------------|
| expression.csv   | CSV  | SYMBOL + 样本列   | 表达矩阵        |
| group.csv        | CSV  | sample, group    | 分组信息        |

## 输出文件

| 文件                    | 目录           | 说明           |
|------------------------|---------------|---------------|
| 01.DEGs.tsv            | result/DEGs/  | 差异基因列表（含逗号风险用 TSV；无逗号问题可用 CSV） |

| 03.volcano.png/.pdf    | result/DEGs/  | 火山图          |

| 参数            | 默认值  | 说明               |

## 阶段与功能边界

| 阶段 | 输入 | 产物 | 不会执行 |
|------|------|------|----------|
| init | 模块模板 | 一份分析配置 | 不创建运行目录 |
| calculate | 配置与业务输入 | 表格、正式缓存、日志 | 不作图、不生成报告 |
| plot | 配置与有效缓存 | 全部约定图形、日志 | 不重新计算 |
| full | 配置与业务输入 | calculate + plot 产物 | 本模块不提供报告阶段 |

## 输入模式与优先级

- 支持的输入：表达矩阵文件 + 分组文件，二者必须在同一份分析配置中明确指定。
- 不支持：直接读取未声明的目录、自动猜测最新文件、同时传入多组互斥业务输入。
- 参数优先级：帮助中声明的命令行覆盖 > 分析配置 > 默认值；未知配置键直接报错。

└── result/              # 正式表格和图形

## 缓存契约

- 缓存包含 `de_table`、`top_genes_mat` 和 `heatmap_annotation`，足以重建本模块全部约定图形。
- `cache_manifest.json` 记录 schema、生产 run_id、输入/计算指纹、对象校验和及实际运行时版本。
- 输入或计算参数变化、清单不兼容、对象缺失或校验和不符时，`plot` 非零退出且不静默重算。
- 正式缓存不随临时文件清理；显式清理方式及保留代次数见 `./run.sh --help`。

## 日志与排错

- 读取 `.run_id` 定位最近成功调用，再查看 `log/<run_id>/<stage>.log`。
- 失败调用不会覆盖 `.run_id`；其 stderr 会给出对应日志路径和退出码。
- 日志同时记录当前 run_id 与缓存生产 run_id、配置来源/覆盖项、缓存命中或拒绝原因。

📊 文件格式建议

📊 数据文件格式

  • 表格输出：根据字段内容选择 .tsv 或 .csv；含化合物名、药物名、通路名、描述等可能出现逗号的字段时使用 .tsv，避免列解析被逗号破坏；确认无逗号解析风险且下游兼容时可使用 .csv
  • R数据：使用 .qs2 保存（qs2 R 包，替代 .rds/.RData）
💡 为什么使用 .qs2 而不是 .rds/.RData？
  • .qs2（qs2 R 包）是更现代的二进制格式，性能更好
  • 跨平台使用方便，但仍需在缓存清单中记录 R、qs2 和关键包版本并校验兼容性
  • 压缩比更高，文件更小
  • 读写速度更快

📈 图表文件格式

  • 输出格式：默认保存 PNG + PDF；[Plot].formats 可选择模块声明支持的一个或多个格式
  • 字体要求：默认 sans-serif；允许配置已安装且模块支持的字体族，必须记录请求字体、实际字体及回退行为
  • PNG：默认 300 dpi，可通过 [Plot].dpi 调整；R 推荐 png(type = "cairo") 以兼容无头服务器
  • PDF：矢量格式；R 推荐 cairo_pdf() 或 ggsave(device = cairo_pdf)，并校验字体嵌入和中文显示
  • 尺寸与外观：默认单面板图 6×4 in；尺寸、单位、主题、色板、字体和基础字号均由 [Plot] 控制
  • 特殊情况：交互图表使用 .html（Plotly等）
⚠️ 以配置和模块能力共同确定验收清单

默认配置生成 PNG 与 PDF；若用户显式选择其他受支持格式，运行日志必须记录请求值和实际产物。

不支持的格式、主题或字体应在绘图前报错，不得静默忽略。
