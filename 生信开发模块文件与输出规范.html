生物信息学 · 模块开发规范

生信开发模块文件与输出规范

v2.2 将源码组织、五阶段执行、配置、结果、报告和验收写成一套可直接落地的规则。模块的计算、作图和报告必须分开实现；full 只负责按顺序串联它们。

init → calculate → plot → report full 串联四阶段 plot 复用 calculate 结果 report 复用表和图 结果平铺、编号稳定

1. 适用范围与判定依据

本规范适用于 RawData 处理、差异分析、富集分析、单细胞分析、模型评估及其他可独立交付的生信模块。模块必须有唯一公开入口、稳定的输入输出接口和可追溯的运行记录。

事项判定依据落地位置
本次目标用户需求或项目 SPECREADME、配置和模块合同
应实现的科学语义官方软件文档、方法论文和官方数据定义doc/source-review.md 及其资料记录
本次实际结果实际执行的代码、配置和数据result/、report/、日志
公开接口模块合同中声明的命令、字段、格式和路径module_contract.yaml 与 README
发生冲突时人工审定。源码不因为“已有实现”就自动正确，官方资料也不能让程序凭空产生结果。先记录冲突和影响，再由指定人员决定保留、修改或暂不支持；决定前不得静默替换算法、参数、图件或结论。

官方资料的 URL、DOI、版本和访问日期只用于来源追溯。它们不是结果，不应被自动写进报告正文。

2. 开发前源码审定

新建、迁移、重构以及计算、统计、绘图逻辑的实质变更，第一步都是基于现有源码建立审定记录；先收集资料并存入模块文档，避免每次运行重新搜索。

  1. 列出原始入口、核心脚本、配置文件、主要输出、绘图调用、报告模板和报告生成代码。
  2. 收集对应官方文档、方法论文、数据库或参考资源的名称、版本、URL/DOI、访问日期和关键定义。
  3. 逐项对照输入对象、ID 体系、算法、统计单位、比较方向、阈值、随机过程、图形编码和输出字段。
  4. 用真实执行命令验证代码实际做了什么，并保存样本数、对象数、关键统计量和结果文件。
  5. 对每个差异写出影响、拟议处理和审定结论；未审定的差异不得进入正式图或报告。
记录项最低内容
官方定义方法名称、版本、输入要求、统计定义、限制和必要摘录。
源码实现文件/函数位置、实际参数、分支条件、读取和写出位置。
真实执行命令、数据版本、样本/对象计数、输出表和图件。
审定结论一致、暂定、需决策或阻断；不得只写“基本一致”。
图件也必须走同一条链。最终图只能由实际执行代码和实际数据生成，不能拿官网图片另画一套来替代源码结果。若官方定义要求源码缺少的图，先审定新增分析，再用真实数据执行并把新增图登记为新产物。

3. 模块源码目录

源码目录和运行输出目录必须物理分开。顶层入口稳定，阶段代码各自归位；复杂模块可在阶段目录下继续拆分，但不能把计算、作图和报告混写。

module/
├── run.sh                         # 唯一公开入口
├── README.md                      # 用途、输入、输出、阶段和运行示例
├── CHANGELOG.md                   # 版本变更
├── module_contract.yaml           # 公开命令和产物合同
├── config/
│   └── module.config.yaml         # 唯一配置模板（也可统一选用 INI）
├── scripts/
│   ├── init.R | init.py
│   ├── calculate.R | calculate.py
│   ├── plot.R | plot.py
│   └── report.R | report.py
├── report_templates/
│   └── report_template.docx       # 正式报告模板
├── doc/
│   └── source-review.md           # 官方资料与源码交叉核对
├── schemas/                       # 有稳定数据结构时保留
└── demo/data/                     # 只放受控演示输入
  • full 是入口编排，不另写一份重复的算法实现；它依次调用 init、calculate、plot、report。
  • 源码根目录不放 log/、cache/、result/、report/、历史输出或运行时配置副本。
  • 禁止 .gitkeep 空目录、虚拟环境、new/final/v2 平行实现、注释掉的旧算法和未被调用的兼容层。
  • 模板、生成器、配置模板和源码审定记录是正式源码；临时渲染文件、解压目录和一次性审计记录不放在源码目录。

4. 五阶段与代码分工

每个分析模块都公开同一组阶段名称。阶段可以单独运行，也可以由 full 串联；不适用的阶段必须明确报错并退出，不得用空文件或占位结果假装完成。

阶段读取负责写出禁止做的事
init配置模板、输入路径、环境校验配置、准备输出目录、建立本次运行记录不得计算、作图或写报告结果
calculate真实输入、分析配置计算结果表、模型对象和供后续阶段复用的中间对象不得把绘图或报告逻辑混入计算脚本
plotcalculate 已产生并声明的表或对象PNG/PDF 等图件不得重新计算、改动科学结果或读取未声明临时文件
reportcalculate 的结果和 plot 的图件正式报告、结果表插入和图题图注不得重新读原始数据、重算统计或临时重画图
full同一份输入和配置按 init → calculate → plot → report 依次完成全部产物不得复制另一套阶段逻辑或改变单阶段语义
 
bash run.sh init     --config config/module.config.yaml
bash run.sh calculate --config config/module.config.yaml
bash run.sh plot      --config config/module.config.yaml
bash run.sh report    --config config/module.config.yaml
bash run.sh full      --config config/module.config.yaml

按变更范围选择执行方式

变更内容需要执行
报告正文、图题、图注、表述或 DOCX 版式用已发布结果执行 report（report-only），不重跑科学计算。
只改变不影响科学结果的作图代码、主题、字体、尺寸或布局执行 plot；报告嵌入新图时再执行 report。
计算逻辑、统计方法、输入处理、配置、公开合同或输出结构执行完整 full。

run.sh 只负责参数解析、路径校验、阶段编排、日志和发布。无参数或 --help 用简体中文说明用途、输入、输出和示例，并且不创建运行文件；未知参数、输入错误或阶段失败必须非零退出。

5. 配置结构：唯一模板、中文注释、真实生效

  • 一个模块只选 INI 或 YAML 一种主格式，config/ 只保留一份规范模板；运行时使用的副本写到输出目录的 log/。
  • 配置只描述输入、分析、绘图、报告和输出规则，不写本次运行才产生的统计结果、时间戳或临时文件列表。
  • 每个键都必须被实际生产路径读取并产生可观察影响；未知键、非法行、越界值、互斥项和不支持枚举立即失败。
  • 优先级固定为：命令行显式值 ＞ 用户配置 ＞ 模块默认值；运行时不得反写用户模板。
  • 路径字段相对配置文件解析；跨脚本传递前先标准化。每个公开键都要有测试证明它真实接线。

推荐的 YAML 分区

module:
  # 模块名称；字符串；必须与公开入口和报告标题一致。
  name: differential_expression
  # 模块版本；语义化版本；接口变更时升版本。
  version: 1.0.0
input:
  # 表达矩阵路径；相对本配置文件；必须存在。
  expression: data/expression.tsv
  # 分组表路径；sample 必须与表达矩阵列一一对应。
  groups: data/group.tsv
analysis:
  # 分析方法；枚举值由模块合同声明。
  method: DESeq2
  # 显著性阈值；数值；范围 (0, 1)。
  p_value_cutoff: 0.05
  # 随机种子；无随机步骤时删除该键。
  seed: 20260903
plot:
  volcano:
    # 图幅；数值；单位 inch；范围 4–20。
    width: 8
    height: 6
    # 静态图格式；逐项列出，不使用 both 哨兵。
    formats: [png, pdf]
report:
  # 正式模板；相对模块源码根目录。
  template: report_templates/report_template.docx
output:
  # 运行输出根目录；命令行可显式覆盖。
  root: output

INI 使用同样的分区和键名，例如 [analysis]、[plot.volcano]、[report]。注释必须紧邻配置项，写清用途、类型、默认值、单位、边界、依赖和修改影响；键名、函数名、变量名和包名保留标准英文标识，说明文字用简体中文。

6. 运行目录与结果文件

output/
├── .run_id                         # 本次运行标识，内容为 YYYYMMDD_HHMM 或秒级值
├── result/                         # 用户正式业务结果，文件直接平铺
├── report/                         # 正式报告；确有报告时生成
├── cache/                          # 后续阶段真实复用的中间对象
│   └── calculate/                  # calculate 写出、plot/report 读取
└── log/
    ├── run_record.json             # 命令、参数、输入、输出、版本和状态
    ├── init.log                    # 仅执行该阶段时生成
    ├── calculate.log
    ├── plot.log
    ├── report.log
    ├── full.log
    └── module.config.yaml          # 本次实际使用的配置副本

结果目录的固定写法

result/
├── 01.DEG_all.csv
├── 01.DEG_sig.csv
├── 02.volcano.pdf
├── 02.volcano.png
├── 03.heatmap.pdf
└── 03.heatmap.png
  • 正式结果直接放在 result/ 根目录，使用两位数字前缀按分析顺序编号，文件名表达业务含义；不再为同一模块随意创建 tables/、figures/ 等第二层结果目录。
  • result/ 只放用户需要的表、图、模型或数据包；日志、配置副本、缓存、审计记录、manifest、checksum 和报告不放在这里。
  • 每个文件在模块合同和 README 中写明用途、消费者、格式、关键列、单位、数量范围和来源。筛选表（如 01.DEG_sig.csv）是正式结果，只要用途和消费者独立且明确；禁止的是没有独立用途的重复裁剪或改名副本。
  • 同一逻辑图的 PNG 和 PDF 是同一结果的两个交付格式，使用同一编号和语义；不能把不同版本图混在一起。
  • 合法的零结果仍输出带表头的空 TSV/CSV，并在日志中说明零结果原因；不适用的图或报告整项省略，不生成空白占位图。
  • 模块间只通过已声明文件接口传递（TSV、CSV、必要时的 .qs2 等），禁止依赖全局变量、共享内存或未记录的临时文件。上游文件、列名、版本和完成标志写入 README，并在启动时检查。

7. 报告结构与机械生成

报告开发负责把正文模板、动态结果槽位、表格、图件、图题图注和 R/Python 生成器写好并提交到模块源码。模块运行时由生成器读取已发布的 calculate 表和 plot 图，机械填充 DOCX；不在运行时临场编造科学文字、数字或图片。

report_templates/
└── report_template.docx             # 唯一正式模板，含 bookmark/marker
scripts/report/
└── generate_report.R | generate_report.py
output/report/
└── module_report.docx               # 同一逻辑报告的正式文件

固定正文顺序与槽位

顺序正文槽位应写内容
1标题与分析概述模块、数据对象、分析目的和一句话方法；不得写问句或任务清单。
2数据来源与分析范围数据集、样本/对象数、分组、输入文件和本次边界。
3材料与方法、参数方法版本、关键参数、阈值、统计单位、比较方向和随机种子。
4质控与数据检查适用的质量指标、样本对齐、缺失/过滤情况；不适用时写明原因。
5结果摘要先写结论，再给实际数字、方向和结果文件位置。
6图表展示与解读图/表紧跟对应段落；每图有唯一图题和完整图注。
7综合结论、限制与待验证只回收已展示证据，明确关联、模型提示和未完成验证，不升级为因果或疗效。
8公开输出文件按逻辑产物列文件名、格式、内容和用途；不把报告自身列成输入结果。
9软件、资源与版本R/Python、关键包、数据库、参考资源和执行版本。
10附录（可选）完整参数、补充表、阴性结果和辅助图；不得把内部审核过程塞进正文。

结果段、图注和天蓝色 Note

  • 每个分析点按“观察结论 → 数字证据 → 图表/文件 → 有边界的解释 → 限制或下一步”生成；不能只写“结果见文件夹”。
  • 图题用陈述句；正文、图题、图注不得出现“哪些、如何、是否、请判断”等问句或任务句。内部问题只能留在开发记录，不能进入成稿。
  • 每幅图必须有唯一编号、对象、比较组、样本或对象数、轴和单位、颜色/线型含义、统计量/阈值、面板说明及阅读边界。图题、完整图、图注必须相邻。
  • 方向、单位、统计边界或阴性结果需要单独提醒时使用天蓝色 Note：边框 #5B9BD5，填充 #DDEBF7，标签 #2F75B5。Note 只由真实结果触发，不放运行状态或泛化套话。
  • 模板中的结果表、公开输出表、版本表和图件位置固定；表格重复表头且数据行不可拆分，长图注不与图分离。
  • 报告默认放在 output/report/，DOCX 为默认交付格式；PDF/HTML 只能是同一逻辑报告的派生格式，不复制正文到 result/。
  • 报告只读已声明的结果表、图件和版本记录，不重读原始输入、不重算统计、不临时重画未声明图。缺事实、缺列或缺图时停止发布，不能用 NA、错误文字或占位图填空。
报告变更边界：只改正文、图题、图注、表述或 DOCX 版式，使用已发布结果执行 report；只改不影响科学结果的作图实现，先执行 plot，需要更新嵌图时再执行 report；只有计算、科学逻辑、配置、合同或输出结构变化才执行 full。

8. 路径、日志与缓存

路径

  • 输入、配置、输出、日志和跨阶段路径在存在性检查、读写和记录前先用 normalizePath 或语言等价方法标准化。
  • 核心流程不得依赖 setwd、硬编码绝对路径或未经检查的字符串拼接；同一文件在代码、日志和报告中使用同一规范路径。
  • 路径越界、缺失、无权限、软链接指向不明或输入类型不符时立即失败，并把错误写到 stderr 和日志。

运行标识与日志

  • 启动时生成一个统一 run_id，写入输出根目录的 .run_id；日志、缓存、结果和报告都记录同一标识。
  • 阶段日志至少记录时间、入口和版本、完整命令、配置副本、输入文件、样本/对象计数、关键参数、输出文件、统计摘要、警告、错误和退出码。
  • log/run_record.json 保存机器可读运行事实；人类日志按阶段分段，不用多个时间戳文件表达同一次运行。
  • .run_id 内容至少精确到分钟，如 20260903_1430；同一天多次运行必须可区分，时间戳不写进日志文件名或配置文件名。

缓存

cache/ 只保存下一阶段真实会读取的计算对象或快照，并记录来源、结构版本、参数指纹和 run_id。纯作图参数改变不应使计算缓存失效；缓存缺失或损坏时明确失败，不静默重算。

计算结果需要被作图或报告复用时，优先保存为可读取的 .qs2、.tsv 或 .csv；作图脚本直接读取该文件，不复制计算代码。

9. 代码要求

错误处理与命名

项目要求
退出码0 成功；1 一般运行错误；2 输入或配置校验失败；3 依赖/环境异常。
Shell使用 #!/usr/bin/env bash 和 set -euo pipefail；变量加引号；临时文件配合 trap 清理。
R关键步骤用 tryCatch；记录错误后以非零状态退出；临时资源用 on.exit 清理。
Python入口用 try/except；记录异常后 sys.exit；禁止 except: pass。
命名R/Python 函数和变量使用 snake_case，类名使用 PascalCase，常量使用 UPPER_SNAKE_CASE；禁止拼音和无意义缩写。

科学和绘图实现

  • 明确矩阵方向、ID namespace、样本顺序、设计矩阵/contrast、效应量、p/FDR、置信区间、统计单位和过滤计数；不能只写裸 p 值或默认参数。
  • 输入启动时检查编码、关键列、类型、取值、样本对齐、物种/注释版本和缺失值策略；遇到非法值显式报错或记录后按合同处理，禁止静默替换。
  • 图表统一记录 renderer、字体、尺寸、DPI、色板和实际参数；静态图默认同时输出 PNG 和 PDF，PNG 推荐 300 dpi，图内使用清晰的无衬线字体并保证色盲可读。
  • R/Python 业务代码新增或修改的注释使用简体中文，说明为什么、边界和改动风险；函数名、变量名、包名、公式和标准术语保留英文。
  • 不得用 wrapper、mock、stub、placeholder、synthetic 或 fallback 替代原始算法；计算结果变量不得被后续代码无意覆盖。
